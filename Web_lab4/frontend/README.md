# Лабораторная работа №4 — Frontend на React

Система управления студентами. Frontend реализован на React и взаимодействует с REST API на Spring Boot из лабораторной работы №3. Данные хранятся в файловой базе H2.

## Возможности

- Регистрация, вход, выход и просмотр профиля.
- Авторизация с access- и refresh-токенами, автоматическое обновление токенов при ответе `401`.
- Роли: `USER` — просмотр студентов; `ADMIN` — просмотр, создание, редактирование и удаление.
- Список студентов, подробная карточка, поиск, фильтрация, сортировка и пагинация.
- Хранение параметров списка в URL.
- Обработка поиска и фильтров через RxJS: задержка 300 мс, пропуск повторов, отмена предыдущей загрузки при поступлении новых параметров после задержки.
- Клиентская валидация, сообщения об ошибках и индикаторы загрузки.
- Защита от повторной отправки форм.
- Отмена удаления в течение 10 секунд через интерфейс. Обновление страницы в той же вкладке не сбрасывает срок отмены.
- Адаптивный интерфейс.

## Технологии

Frontend: React, React Router, Context API, RxJS, Vite.

Backend: Java 17, Spring Boot, Spring Security, JWT, Spring Data JPA, H2.

Запуск: Docker Compose, многоэтапная сборка, Nginx.

Тестирование frontend: Vitest, React Testing Library, jsdom.

## Запуск через Docker

Требуются Docker и Docker Compose. На macOS и Windows можно использовать Docker Desktop.

Выполните команды из корня проекта — папки, содержащей `docker-compose.yml`:

```bash
docker compose up --build
```

После запуска откройте http://localhost:8080.

Запуск в фоновом режиме:

```bash
docker compose up -d --build
```

Учебная учётная запись администратора при настройках по умолчанию:

- Логин: `admin`
- Пароль: `Admin12345`

При регистрации создаётся пользователь с ролью `USER`.

Остановка приложения:

```bash
docker compose down
```

Данные H2 сохраняются в томе `students-data` между перезапусками и обычными остановками контейнеров.

## Обновление после изменения кода

После изменения frontend, в том числе `src/styles.css`:

```bash
docker compose up -d --build frontend
```

После изменения backend:

```bash
docker compose up -d --build backend
```

Просмотр состояния и логов:

```bash
docker compose ps
docker compose logs -f
```

## Конфигурация

Без файла `.env` приложение использует учебные значения по умолчанию из `docker-compose.yml`.

Для собственных настроек скопируйте пример в корне проекта:

```bash
cp .env.example .env
```

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `FRONTEND_PORT` | Порт приложения на компьютере | `8080` |
| `ADMIN_PASSWORD` | Пароль для начального создания администратора | `Admin12345` |
| `JWT_SECRET` | Ключ подписи JWT | Учебный ключ из `.env.example` |
| `JWT_ACCESS_SECONDS` | Срок действия access-токена, секунды | `900` |
| `JWT_REFRESH_SECONDS` | Срок действия refresh-токена, секунды | `604800` |

Для использования вне учебного окружения задайте собственные пароль администратора и ключ JWT. Ключ должен содержать не менее 32 байт UTF-8.

После изменения `.env` повторите `docker compose up -d --build`.

## Страницы

| Адрес | Назначение | Доступ |
| --- | --- | --- |
| `/login` | Вход | Без авторизации |
| `/register` | Регистрация | Без авторизации |
| `/profile` | Профиль текущего пользователя | `USER`, `ADMIN` |
| `/students` | Список студентов | `USER`, `ADMIN` |
| `/students/:id` | Карточка студента | `USER`, `ADMIN` |
| `/students/new` | Добавление студента | `ADMIN` |
| `/students/:id/edit` | Редактирование студента | `ADMIN` |

Права проверяются компонентом `Guard` на frontend и независимо от него — Spring Security на backend.

## Как работает приложение

Nginx отдаёт собранные HTML, CSS и JavaScript. Переходы между страницами обрабатывает React Router без полной перезагрузки документа.

Браузер отправляет запросы на `/api/...` по адресу приложения. Nginx пересылает их сервису `backend:8000` во внутренней сети Docker Compose. Внешний порт backend в текущей конфигурации не публикуется.

`AppContext` хранит сессию, роль, уведомления, состояние отмены удаления и счётчик `revision`. После изменения данных `changed()` увеличивает счётчик, что позволяет повторно загрузить список.

`useStudents` передаёт параметры в `BehaviorSubject`. Функция `createListStream` применяет `debounceTime`, `distinctUntilChanged` и `switchMap`. При переключении загрузки отписка вызывает `AbortController.abort()`. Ошибки отдельных запросов не останавливают последующие поиски.

Сессия хранится в `sessionStorage` и публикуется через `session$`. HTTP-клиент добавляет access-токен, при `401` пытается обновить токены и повторяет исходный запрос один раз. Параллельные запросы используют общий запрос обновления токенов.

Удаление на backend мягкое: запись получает `deleted = true`. Интерфейс предлагает восстановить её в течение 10 секунд. Ограничение времени реализовано на frontend. Формы сохраняются по кнопке; автосохранения нет.

## Основные запросы API

| Метод | Адрес | Действие |
| --- | --- | --- |
| `POST` | `/api/auth/register` | Регистрация |
| `POST` | `/api/auth/login` | Вход |
| `POST` | `/api/auth/refresh` | Обновление токенов |
| `GET` | `/api/auth/me` | Получение профиля |
| `GET` | `/api/requests` | Список студентов |
| `GET` | `/api/requests/{id}` | Получение студента |
| `POST` | `/api/requests` | Создание студента |
| `PUT` | `/api/requests/{id}` | Полное обновление студента |
| `DELETE` | `/api/requests/{id}` | Мягкое удаление |
| `POST` | `/api/requests/{id}/restore` | Восстановление |

Пример параметров списка: `/api/requests?search=Иван&page=0&size=10&sortBy=fullName&direction=asc`.

Нумерация страниц API начинается с `0`. Количество записей и страниц возвращается в заголовках `X-Total-Count` и `X-Total-Pages`.

## Локальная разработка frontend и проверки

Требуется Node.js 22.12 или новее.

```bash
cd frontend
npm ci
npm run dev
```

Vite по умолчанию проксирует `/api` на `http://localhost:8000`. Для работы с данными нужен запущенный backend, доступный по этому адресу. При запуске backend только через текущий Docker Compose его порт с компьютера недоступен; для режима Vite запустите backend локально или отдельно настройте публикацию порта.

Проверки из папки `frontend`:

```bash
npm test
npm run build
```

`npm test` запускает тесты, `npm run build` собирает приложение в папку `dist`.
