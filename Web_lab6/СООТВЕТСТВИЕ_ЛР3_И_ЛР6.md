# Соответствие ЛР6 исходной лабораторной №3

Основа: `Web_lab3(20261123-171423).zip`. Это архив **ЛР6**, адаптированный к контрактам ЛР3. Исходную ЛР3 менять не требуется.

## Маршруты исходной ЛР3
- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/refresh`.
- `QUERY /api/requests?page=0&size=100&sortBy=id` — JSON-массив, число записей в заголовке `X-Total-Count`.
- `QUERY /api/requests/{id}`, `POST /api/requests`, `PUT /api/requests/{id}`, `PATCH /api/requests/{id}`, `DELETE /api/requests/{id}`.
- Модель: `id, fullName, group, isuId, dormitory, room, moveInDate, isForeigner, notes`.
- Роль `ADMIN` может изменять студентов, `USER` — просматривать.

## Расширения Java в составе ЛР6
- `QUERY /api/auth/me` проверяет access-JWT и возвращает `id, username, email, role`, используемые Node.js.
- `QUERY /api/requests/{id}` возвращает ETag, а `PUT`/`PATCH` проверяют заголовок `If-Match` для контроля конкурентных изменений.
- После коммита изменения Java отправляет событие в Node.js на `/internal/events` с ключом `x-service-key`.
- Rate limiting, WebSocket, CSV-обработка и аудит.

**Важно:** для запуска ЛР6 используйте Java-бэкенд **из этого архива**, а не отдельно исходную ЛР3: в исходной ЛР3 отсутствуют `/api/auth/me`, ETag/If-Match и доставка событий. При этом исходные маршруты и поля ЛР3 сохранены.

## Конфигурация
- `JAVA_URL=http://java-backend:8000` — имя сервиса и порт из Docker Compose.
- `JAVA_PROFILE_PATH=/api/auth/me`.
- `JAVA_STUDENTS_PATH=/api/requests`.
- `VERSION_FIELD` не задаётся: контроль конфликтов реализован через HTTP ETag.

## Запуск и проверки
1. Создать `.env` рядом с `docker-compose.yml`, задать `ADMIN_PASSWORD`, `JWT_SECRET`, `SERVICE_KEY` (два последних — разные надёжные секреты, например `openssl rand -hex 32`).
2. Выполнить `docker compose up --build`.
3. Открыть `http://localhost:8080`, проверить авторизацию, CRUD студентов, аудит, WebSocket и CSV.
4. `cd node-realtime && npm test` запускает тесты Node.js.

## Ограничения
- Java отправляет события после коммита, но не реализует гарантированную повторную доставку при сетевых ошибках.
- Реальный запуск Docker и Java нужно дополнительно проверить в целевом окружении.
